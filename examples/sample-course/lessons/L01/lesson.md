# 第 01 课｜从“找到最大值”理解真正的算法

> **适用对象：** 没写过程序、刚学过变量和条件判断的学生。**阅读方法：** 第一次从头读并完成预测；复习时先看“复习速览”，闭卷回答后再核对“答案与解析”。
>
> 本课为独立设计的虚构教学示例，并非对某位真实教师的课堂、习题或板书的复制。涉及 C 语言行为时以下默认采用 C17 标准，具体编译器和机器的实现差异要单独核对。

## 本课导读

想象你负责整理一组室外温度读数，系统要报告其中的最高温度。你当然可以盯着数字直接说出答案，但如果明天收到五千条记录，或者所有温度都是零下，又或者最高值出现不止一次，单凭“看出来了”就无法得到一个能重复使用的方法。**程序设计的第一步不是敲代码，而是把任务要求拆成明确、有限、可检查的步骤。**

本课将解决三个连续问题：怎样把“找出最大值”变成算法；怎样选择不会在特殊输入下出错的初始状态；怎样证明我们每检查一个数字都没有丢失已获得的信息。我们还会进一步统计最高值出现的次数，看看一个简单算法如何在需求变化时扩展，而不是推倒重来。

初学者请先理解“当前最大值”为什么会变化，再做例题。已经学过循环的学生可以直接看不变量、常见错误和分层作业，最后通过复习速览检查是否真正理解。只看代码、不解释运行过程，不算掌握本课。

## 预备知识

**变量**可以理解为一个有类型的存储位置：我们把当前已经发现的最大数值放在变量 best 中，读取下一个数字后可能更新它。这里的“最大”不是预测未来，而是指**已经检查过的数字**中的最大值；程序只有处理完全部输入，才能说它是整组数据的最大值。注意：变量名 best 只是我们起的名字，C 语言并不知道它应该保存最大值，这个意义由代码的规则保证。

**比较运算**回答一个是或否的问题，例如 x > best 判断新值是否严格更大，x == best 判断是否等于当前最大值。关系表达式在 C 中求得整数结果，真为 1、假为 0。条件语句只根据表达式的求值结果选择执行路径，不负责判断你的初始化是不是合理。

**数组和下标**让我们能够按顺序读取一组数。a[0] 表示第一个元素，a[1] 是第二个；当数组有 n 个元素时，有效下标从 0 到 n-1。访问 a[n] 超出范围，不能把它当作“循环结束的标记”。如果你对数组还不熟，可以先把输入看成写在纸上的一排数字，并按从左到右的次序手工查看。

**循环**让同一个检查动作重复执行。理解循环时要同时回答：开始前变量是什么；每轮检查哪个元素；什么条件下修改状态；什么时候停止。后面的代码只是对这四个问题的准确表达。即使暂时不会编译，你也能通过表格完成本课主要推理。

## 核心知识详解

### K01 · 从任务要求走向可执行算法

**为什么要学：** “请找出最大值”是一句任务描述，不是一份完整操作说明。不同人看一眼小数组都可能给出同样答案，但机器没有“凭直觉找”的步骤。如果不能解释具体处理顺序、输入和结束条件，就很难知道程序面对负数、重复值或长列表时是否还能正确。算法首先是解决问题的有限步骤，并不依赖某一种编程语言。

**直观理解：** 可以把整个过程想成一个不断更新的记录本。第一次查看数字时，记录本只知道一个候选值；每遇到下一个数字，都把它同记录本里的值比较。如果更大，就替换候选值；如果不更大，原记录就足够好，没有必要回头重新看已经处理过的数据。这就把一个整体问题拆成“重复做一件小事”，也为后续使用循环提供了理由。

**准确规则：** 对**非空**的有限数字序列，先令 best 等于第一个元素；随后从第二个元素到最后一个元素逐个比较。若当前元素大于 best，令 best 取该元素；否则保持 best。处理完毕后返回 best。输入必须是可以比较大小的数值；如果序列为空，初始化步骤无法执行，必须事先定义独立的空输入行为，例如返回“无有效数据”而不是伪造一个数。

**逐步推演：** 用原创数据 5、-3、8、8、1 演示。开始查看第一个元素，best=5。第二个元素为 -3，比 5 小，因此 best 仍为 5。第三个元素为 8，比 5 大，于是 best=8。第四个元素也是 8，并没有严格大于 best，所以 best 保持不变。最后一个元素为 1，仍然不更大。到达序列尾部时，我们已经把每个元素与当时的最优候选值比较过，返回 8。这个过程不是“随便试几次就行”，而是每次状态变化都遵循同一条规则。

**检查理解：** 如果把数字顺序改成 8、5、1、-3、8，答案会变吗？不会，因为算法寻找的是大小而不是出现位置。但每一步 best 的变化过程会不同。再想想，如果把比较从 > 改成 >=，最终最大值通常仍相同，却可能影响“最大值第一次出现在哪里”这样的额外需求；所以看起来微小的条件变化也要结合需求判断。

### K02 · 初始化和边界条件决定算法是否可靠

**为什么要学：** 很多代码在普通正数输入下能成功，却在特殊情况失败，不是循环写错，而是最开始的假设没有根据。例如把 best 初始化成 0，看似简单，但 0 并不是输入里必然存在的值。错误初值会让循环在某些输入下永远无法修正结果。因此，设计算法时必须明确“初始状态为什么正确”。

**直观理解：** 假设你负责选出一支队伍中跑得最快的人。还没见到任何人之前，不能凭空指定一个不存在的参赛者当冠军；见到第一位后，才有了“当前最好”的合理起点。数字最大值也是一样。特别是当所有值都小于 0 时，凭空写入的 0 会变成一个不属于任何输入的假冠军。

**准确规则：** 对非空输入使用 a[0] 初始化，再从 i=1 开始比较，能确保 best 始终来自输入。循环条件必须保证 i<n，否则最后一步可能访问不存在的 a[n]。如果 n 是 0，则不能执行读取 a[0] 的步骤。题目还需要说明出现相同最大值时是否要保留首次位置、最后位置或计算出现次数：这三种要求对应不同的状态更新规则，不能凭代码作者的喜好混用。

**逐步推演：** 考虑 -4、-9、-2。错误方法设置 best=0，随后依次判断 -4>0、-9>0、-2>0，结果三次都为假，返回错误答案 0。正确方法令 best=-4，之后看到 -9 时保持 -4，看到 -2 时更新为 -2，最终返回真实存在于数组中的最大值。再考虑单元素数组：初始化后没有第二个元素，循环可以执行零次，返回唯一元素；这正是算法应有的行为，而不是异常情况。

**检查理解：** 对于全部为负的数组，最小值算法是否也能随意把初值设为 0？如果求最小值，0 可能在负数输入中被合理更新，但对全部为正的数组又会失败。因此不是“求最大值用负无穷、求最小值用正无穷”就一定适用于所有类型；最可靠的通用做法仍然是确认输入非空后采用第一个真实元素。

### K03 · 用循环不变量说明算法为什么正确

**为什么要学：** 会手工列出一次正确答案，不能证明算法面对各种输入都正确。要建立对循环的信心，我们需要说清楚一件每轮都成立的事实，并确认下一轮不会把它破坏。这叫**循环不变量**。它既能用于写出正确程序，也能用于定位隐藏很深的逻辑错误，是从初学者走向算法设计的重要一步。

**直观理解：** 把已经检查过的数据看成一个逐渐扩大的盒子。刚打开盒子时，只有第一个数字，best 必然是它的最大值。每次向盒子里再放一个数字，只需要比较新放入的数字与旧 best：如果新值更大，新的最大值就是新值；否则旧 best 仍是最大值。我们并不需要重新扫描整个盒子，因为关于旧元素最重要的信息已经浓缩在 best 中。

**准确规则：** 在每轮准备处理第 i 个元素时，best 等于已经处理的前 i 个元素中的最大值。初始时，已经处理一个元素，best=a[0]，命题成立；处理 a[i] 时，如果它大于 best，就更新，否则保持，因此处理完它后 best 等于前 i+1 个元素的最大值；当 i==n，全部元素都已处理，所以 best 是整个非空序列的最大值。这个证明依赖合法下标、明确的比较关系和输入不会在遍历期间无故改变。

**逐步推演：** 仍用 5、-3、8、8、1。处理第一个元素后，已处理集合是 {5}，最大值为 5。处理第二个后，集合变成 {5,-3}，最大值为 5。第三个后，集合为 {5,-3,8}，最大值为 8。第四个元素也是 8，集合最大值仍为 8。最后加入 1 后，最大值仍为 8。观察每一步：best 不只是一个可能的答案，而是一个可以对照已处理前缀逐项核验的严格承诺。

**检查理解：** 如果在每轮结束时 best 不等于已处理前缀中的最大值，应该先查哪里？通常先查初始值、比较条件或更新语句，因为不变量的建立与保持都依赖它们。将这个判断方法迁移到“当前最小值”“当前总和”“已处理元素个数”时，只需把不变量的含义改写，就能组织新的循环算法。

## 例题精讲

**题目：** 现在希望找出一组非空整数中的最大值，并统计最大值出现了多少次。请对原创数据 -4、-9、-2、-2、-7 设计 C 程序；先手工预测答案，再解释每个变量的含义，并说明相同最大值出现时为什么不能简单忽略。

**思路：** 只有 best 不够，因为它只能告诉我们数值是多少，不能告诉我们出现次数。增加 count 记录**当前最大值在已检查元素里出现的次数**。初始化时 best 是首元素，count=1；若遇到更大的元素，旧最大值被淘汰，count 必须重置为 1；若遇到等于 best 的元素，count 增加 1；若遇到更小的元素，两个变量都不变。初学者最容易漏掉的恰恰是“找到更大值时为什么要重置次数”。

**逐步推演：** 开始 best=-4、count=1。遇到 -9，它更小，状态保持 (-4,1)。遇到 -2，它更大，状态变为 (-2,1)。再遇到 -2，它等于当前最大值，状态变成 (-2,2)。遇到 -7 时没有变化，结束得到 (-2,2)。这五轮追踪每一步都能对照前缀集合检查：best 是当前前缀最大值，count 是这个最大值在前缀出现的次数。

~~~c
#include <stdio.h>
#include <stddef.h>

int main(void) {
    int data[] = {-4, -9, -2, -2, -7};
    size_t n = sizeof data / sizeof data[0];

    int best = data[0];   /* 此示例数组确定非空 */
    size_t count = 1;

    for (size_t i = 1; i < n; ++i) {
        if (data[i] > best) {
            best = data[i];
            count = 1;
        } else if (data[i] == best) {
            ++count;
        }
    }

    printf("max=%d count=%zu\n", best, count);
    return 0;
}
~~~

**结果：** 按照上述完整追踪，可以预测输出 max=-2 count=2。这里的 %zu 对应 size_t 类型，而 %d 对应 int 类型；格式说明与参数类型必须匹配。代码未在此文档中声明已经执行，因此该结果属于根据程序逻辑推导出的预期结果，实际验证应由本地编译器完成。

**验证：** 可以使用符合 C17 的编译器并开启常见警告，例如 clang -std=c17 -Wall -Wextra -pedantic demo.c -o demo 后运行。然后分别尝试全正数、全负数、相同数字和只有一个元素的数组。检查的不只是最终 best 是否正确，还包括 count 与当前最佳值出现次数是否一致。对于真正接收用户数据的程序，还必须先检查是否至少输入一个元素，不能把这里确定非空的示例生搬硬套到空输入场景。

**变式：** 如果题目要求得到第一次出现最大值的位置，就再维护位置变量；遇到严格大于时更新位置，遇到相等则不要改位置。若要求最后一次出现位置，就在相等时更新位置。这个变式说明“正确算法”不只是套一种固定代码，而是理解每个更新条件与任务定义的关系。

## 易错点与纠正

**错误一：把初始化当成随意赋值。** 令 best=0 对一些正数例子碰巧正确，却不能解决全负数问题。错误的直接后果是返回一个原数组根本没有出现过的数字。正确做法是在确认输入非空后选择首元素作为初值。为了防止此类错误，测试时必须刻意加入全部为负数、全部为正数和只有一个数的情况，而不只是测试常见的混合正数。

**错误二：循环边界多写一位。** 当 n 个元素的下标是 0 到 n-1 时，i<=n 会尝试访问 a[n]。在 C 语言中，越界访问属于未定义行为，不能根据某次恰好输出了什么就认为程序有规律可循。应当写 i<n，并在脑中画一张下标表：第一个元素是 0，最后一个是 n-1，n 表示已经处理完毕的位置。

**错误三：更新最大值却忘记重置次数。** 当新元素比 best 大时，新值是新的最大值，旧 best 的出现次数已经与新目标无关。因此必须同时让 count 回到 1。否则计算会把旧最大值的出现次数累加到新最大值上，返回的数值正确但统计错误。可以用“先重复旧最大值，再出现一个更大值”的测试数据发现这个问题。

**错误四：把正确输出误当成正确解释。** 一段代码可能在某几组数据上给出正确答案，但仍存在没有被触发的边界漏洞。每次检查时，应同时说明初始不变量、循环保持过程和结束条件，再用不同类型的输入挑战它。如果只会给出结果却说不清为什么所有合法输入都适用，说明理解还需要巩固。

### Q01【基础】手工追踪最大值

**学习目标：** 通过 K01 识别任务与算法的区别，使用“当前最大值”状态完成全过程追踪。**任务：** 对 6、1、9、4、9 逐个比较，不省略任何一轮；每一步写出读取的元素与更新后的 best，解释为什么最终结果不受中间较小数的影响。**提交内容：** 一张至少五行的追踪表与一段完整的解释。**验收标准：** 初始值正确，五个前缀的最大值都正确，结束时给出 9，解释能与状态变化对应。**提示：** 从第一个真实元素建立初值，每次只问“新读入的数是否严格大于 best”。

### Q02【基础】检查不合理的初始化

**学习目标：** 根据 K02 解释为什么特定初始化可能破坏程序正确性。**任务：** 某人求最大值时把 best 初始化为 0，请分别用 -8、-3、-5 与 4、6、2 两组输入手工执行比较，并设计一个不会受这两组数据影响的初始化方式。**提交内容：** 两组追踪结果、错误原因和修正后的算法步骤。**验收标准：** 明确指出错误输入会返回 0，解释 0 不是输入元素，且新算法对非空列表正确。**提示：** 想一想：为什么第一位数字与无根据的默认常量具有不同地位？

### Q03【应用】把最大值改为最小值

**学习目标：** 把 K01/K02 的思想迁移到另一个极值问题，并保留边界意识。**任务：** 设计寻找最小值及其出现次数的算法，输入是 7、-1、3、-1、8。请先说明需要修改的比较条件，随后给出完整伪代码或 C 程序，再解释如果所有输入都是正数会怎样。**提交内容：** 设计说明、状态追踪、算法和测试案例。**验收标准：** 最小值为 -1、出现两次；对只有一个元素和全正数组也能给出正确结果。**提示：** 求最小值时，什么时候要重置次数，什么时候要增加次数？

### Q04【应用】定位隐藏的计数错误

**学习目标：** 利用 K03 的“已处理前缀”含义，诊断更新逻辑中隐藏的错误。**任务：** 给出一个错误策略：best 从第一个元素初始化，count=1；遇到更大元素时更新 best 但不重置 count，遇到相等时加一。请构造一个使 count 错误的短数组，并逐轮解释变量变化，写出最小修改。**提交内容：** 反例输入、至少三轮状态表、错误定位与修复理由。**验收标准：** 反例确实使错误策略产生不正确次数，修正后可核对，说明为何不变量被破坏。**提示：** 先让旧最大值出现两次，再安排一个更大的数出现一次。

### Q05【挑战】把需求扩展成可靠接口

**学习目标：** 综合 K01–K03 处理输入限制、结果状态和一致性证明。**任务：** 设计函数接口，从整数数组与元素个数中求最大值、出现次数和第一次出现位置。明确说明空数组如何返回失败状态，并对重复最大值、全负数、单元素和空输入制定测试。至少解释一个实现细节为何使用严格大于而不是大于等于。**提交内容：** 函数签名、核心伪代码或完整 C 实现、四组测试和正确性理由。**验收标准：** 不会读取空数组首元素；所有成功结果与输入一致；第一次最大值位置正确；写出选择状态更新条件的解释。**提示：** 可让函数返回成功标志，用指针参数传回多个结果，但先写清调用方如何判断成功。

## 深入理解

**算法为什么只需要一次遍历？** 每读到一个新元素，关于已处理前缀求最大值所需要的信息都已经集中在 best 里。重新扫描之前的元素不会提供额外信息，因此每个元素最多读取一次，运行时间随 n 线性增加，可写成 O(n)。这里的 O(n) 描述输入规模增长时的趋势，不代表每台机器都在固定时间处理一次比较；不同编译器、缓存与处理器会影响具体耗时。

**能不能比一次遍历更快？** 如果没有额外的输入结构或预先计算的信息，想确定一般无序列表的最大值，原则上必须检查全部元素；因为没检查的那个元素完全可能更大。这里得到的是一个问题本身的信息需求，而不只是代码习惯。若数组已经排序或有额外索引，问题条件变化，所需工作量也可能改变，不能把当前结论不加条件地推广。

**保存哪个位置为什么会改变比较条件？** 如果只关心最大值，遇到相等元素时保持旧位置或换成新位置并不影响最大值数值；但若要返回“第一次出现”，平局时不能更新位置。算法变量的意义是约定出来并通过每一轮保持的。每新增一项需求，都应重新写清楚相应不变量，检查旧的更新规则是否仍然够用。

**跨课联系：** 这里的“前缀状态”思路会继续出现在求平均值、寻找第一个满足条件的元素、对数组排序、统计字符频次与文件顺序读取中。以后学习指针时还会发现，数组元素位置和地址的关系决定了正确的遍历范围；学习函数时则需要用清晰的输入输出契约将整套操作封装起来。

## 复习速览

**必会：** 任务目标不等于算法；对非空序列用首元素初始化 best；从第二个元素遍历到最后一个元素；遇到更大值才更新；循环结束时 best 等于整个列表最大值；所有声明都需要明确适用前提。求次数时新增 count，遇到更大值重置为 1，遇到相同值加 1。

**易错：** 随意把 best 设为 0；没有检查空输入；把 i<n 写成 i<=n；把 C 的一次运行结果当作越界访问的固定行为；最大值更新后忘记重新计数；把第一次出现的位置与最后一次出现的位置混淆。

**自测：** 不看正文，口头回答：①为什么首元素比 0 更适合作初值？②什么是不变量，它在第 i 轮究竟承诺了什么？③为什么新最大值出现时要让 count 回到 1？④若只允许顺序读取，为什么不能跳过未检查的元素？请先回答再核对答案。

**联系：** 变量与赋值负责保存状态；比较和分支负责选择更新；循环负责遍历；数组负责组织输入；函数将算法变成可复用接口。这五个概念不是孤立语法，它们共同组成了最基础的程序设计方法。

## 答案与解析

### Q01 解析

**结论：** 输入 6、1、9、4、9 的各步 best 依次为 6、6、9、9、9，结果是 9。首次看到 9 时发生更新，最后一个 9 与当前最大值相等，若只需要最大数值就不必再更新。

**推理：** 第一轮只检查 6，当前最大值自然为 6；第二轮的 1 不大于 6；第三轮的 9 大于 6，所以候选值变成 9；随后 4 和 9 都不严格大于当前值。关键是保持“当前 best 总是已检查元素的最大值”这一事实，不需要预先知道后面会出现什么。

**错误辨析：** 如果把初始化当作“查看第一个元素之前必须写一个 0”，很容易忽略负数边界。另一个常见错误是把每轮比较的元素和最终 best 混为一谈：看到了 4 不代表 best 应变成 4。要用前缀最大值表解释，而不是只给出最后答案。

### Q02 解析

**结论：** 错误策略对 -8、-3、-5 会返回 0，而正确最大值应为 -3；对 4、6、2 则恰好返回 6。修复策略是先检查输入非空，再把首元素赋给 best，之后从第二个元素开始比较。

**推理：** 对全负数输入，每一个元素与 0 比较时都较小，因此错误初值始终保留到结束。对正数输入则会出现大于 0 的元素，使错误初值被覆盖，故一次通过不能证明初值合理。修复后第一步已经保证 best 是真实输入数据中的元素，后续比较才能维持相应的不变量。

**错误辨析：** 只验证一组正数会错误地认为初始化 0 没问题。把 0 换成某个很小的负数也不是通用答案，因为实际输入范围可能超出预设。若存在空输入，必须通过显式失败状态处理，而非凭空指定一个“最大值”。

### Q03 解析

**结论：** 对 7、-1、3、-1、8，最小值为 -1，出现两次。将比较方向改成“新值小于当前最小值”，在找到更小值时重置 count，遇到相等时增加 count。

**推理：** 初始化 smallest=7、count=1。遇到 -1 后，smallest=-1、count=1；遇到 3 时保持；再次遇到 -1 时 count=2；遇到 8 后保持。每轮满足“smallest 等于已处理前缀的最小值且 count 是其出现次数”。对全正数组同样应使用首元素初始化，避免随意设置 0 错误地成为最小值。

**错误辨析：** 仅改比较方向却不调整变量含义，会把最大值计数与最小值计数混在一起。还要注意相等时不应重置为 1，否则重复最小值的次数无法保留；单元素输入应返回次数 1，不能因为循环零次就误判未找到元素。

### Q04 解析

**结论：** 可以使用 5、5、8、1 构造反例。错误实现开始 best=5、count=1，遇到第二个 5 后 count=2；遇到 8 只更新 best，count 错误地保持 2；最后看到 1 时状态不变，得到错误的“最大值 8 出现两次”。

**推理：** 不变量要求 count 统计的是**当前最大值**出现次数。原来 count=2 统计的是数值 5，而 8 首次出现时成为新的最大值，旧计数没有继承的意义。正确分支必须在更新 best=8 的同时执行 count=1，后续遇到相同 8 才累加。通过已处理前缀的逐步表，就能定位具体哪一轮打破了状态约定。

**错误辨析：** 如果只用最大值不发生变化的输入测试，错误代码可能全部通过，因为不存在“重置次数”的场景。设计测试时需要专门触发状态转换，再观察多个变量是否同步更新，不能只检查其中一个结果。

### Q05 解析

**结论：** 函数可以返回状态值表示是否成功，例如当元素个数为零时返回 0，成功时返回 1；通过输出参数交回 best、count 和 first_index。下面是设计思想而非对任何教师原题的答案复制。

**推理：** 首先验证输入指针、输出指针以及 n 是否满足调用约定；仅在有效且非空时初始化 best=a[0]、count=1、first_index=0。从 i=1 访问到 n-1，发现 a[i]>best 时同时更新 best、count=1、first_index=i；相等时只增加 count，不改 first_index。这样处理完前缀后，三个变量始终对应这一前缀的最大值、次数和首次位置。空输入在访问 a[0] 之前退出，避免非法读取。

**错误辨析：** 遇到相同最大值时，如果也更新 first_index，就会错误地保存最后一次出现的位置；如果遗漏 count 重置，则会混入旧最大值次数；如果先读取 a[0] 再检查 n，就会在空输入时发生无效访问。分别测试全负数、重复最大值、单元素和空输入，正是为了针对这些不同错误建立可观察的验证证据。
